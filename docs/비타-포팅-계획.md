# 오르페이아 · 한국사 — PS Vita 포팅 계획 (VitaSDK)

2026.11 초안. 웹판(정적 HTML/JS)을 PS Vita 홈브루(VPK)로 옮기는 계획이다. 이야기·문제·그림은 웹판을 그대로 원본으로 쓰고, 비타판은 **변환 도구 + 네이티브 실행기**로 만든다. 웹판 작업 방식(대본 문법, `tools/`, CLAUDE.md 규칙)은 바꾸지 않는다.

## 1. 지금 게임의 규모 (2026.11 기준)

| 항목 | 양 | 비타에서의 의미 |
|---|---|---|
| 대본 | 25장(서장~종장), 약 9,300줄, 명령 38종(`say` `show` `bg` `choice` `quiz` `battle` `board` …) | 실행기를 새로 짜야 하는 핵심 |
| 문제 | 기출 550 + 오르페이아 예상 150 = 700, 해설 포함 | 데이터만 옮기면 됨 |
| 그림 | 배경 186 · CG 231 · 스탠딩 239 · 문제 장면 134 · SD 12 · 모브 17 (WebP 약 250MB, 2배 업스케일본) | 화면이 960×544라 크기를 줄여야 함 |
| 문제 자료 그림 | 기출 739(`assets/kh`, 107MB) + 예상 150(`assets/qfig`, 13MB) | 글씨가 작아 확대·이동이 꼭 필요 |
| 음악·효과음 | 배경음악 41곡(MP3 172MB) + 효과음 | OGG로 바꿔 용량 절반 |
| 웹 전용 기능 | CSS 연출(흔들림·파편·컷인), DOM 오버레이(갤러리·기록부·판서), localStorage | 모두 다시 구현 |

## 2. 기기 제약

- 화면 960×544(5인치, 앞 터치 + 뒤 터치패드). 웹판 기준 화면(1600×900)의 약 60%.
- CPU ARM Cortex-A9 4코어(앱은 3코어), RAM 512MB(홈브루 앱이 쓸 수 있는 양은 그보다 적다. 기본 약 256MB, 늘려도 300MB대로 잡는다), VRAM 128MB.
- 웹 브라우저 엔진을 쓸 수 없다. 비타 내장 브라우저는 오래된 WebKit이라 이 게임의 JS·CSS를 못 돌린다. 그래서 **웹판을 감싸서 띄우는 방식은 불가능**하고 실행기를 새로 짠다.
- 실행 조건: 사용자의 비타에 HENkaku 계열 홈브루 환경(펌웨어에 맞는 Ensō·h-encore 등)과 VitaShell이 있어야 VPK를 설치할 수 있다.

## 3. 방식 고르기

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **A. C++17 + SDL2 네이티브 실행기** (VitaSDK) | 메모리·로딩을 직접 다룸. 대본 문법을 그대로 해석. PC(리눅스·윈도)에서도 같은 코드로 돌려 개발이 빠름 | 실행기·UI를 전부 새로 짜야 함 | **추천** |
| B. Ren'Py 비타 포트 | VN 기능이 다 있음 | 대본을 Ren'Py 문법으로 바꿔야 하고, 퀴즈·배틀·기록부 같은 이 게임만의 화면을 Ren'Py로 다시 짜야 함. 큰 그림이 많으면 비타 포트는 메모리가 빠듯하다는 평 | 보류 |
| C. Godot 3 비타 포트 | 에디터로 UI 만들기 쉬움 | 커뮤니티 포트라 안정성·성능을 장담하기 어렵고 내보내기 과정이 무거움 | 보류 |
| D. JS 엔진(QuickJS) 내장 + vn.js 재사용 | 웹판 로직 재사용 | vn.js가 DOM·CSS에 깊게 묶여 있어 결국 렌더링을 다 새로 짜야 함 | 제외 |

→ **A안**. 대본은 이미 단순한 줄 단위 문법이라 C++ 인터프리터로 옮기기 쉽고, 웹판 `vn.js`의 파서 규칙을 그대로 따르면 된다.

## 4. 구조

```
orpheia-history/
├─ story/ data/ assets/        ← 원본(웹판과 공유, 그대로)
├─ tools/export-vita.mjs       ← 변환 도구(Node): 대본·문제·그림·소리를 비타용으로
└─ vita/
   ├─ CMakeLists.txt           ← VitaSDK 빌드 + PC(SDL2) 빌드 둘 다
   ├─ sce_sys/                 ← LiveArea(아이콘 128×128, 배경, 시작 화면)
   ├─ src/
   │  ├─ main.cpp              ← 플랫폼 초기화, 메인 루프(60fps)
   │  ├─ script/               ← 대본 인터프리터(op 실행, 플래그, 라벨·점프·@if·@top)
   │  ├─ render/               ← 배경·스탠딩 3자리·대사창·이름표·사진 액자·휴대폰·카드
   │  ├─ text/                 ← FreeType 한글 글리프 캐시, 타자 효과, 줄바꿈
   │  ├─ ui/                   ← 선택지, 퀴즈, 해설, 판서, 기록부, 갤러리, 세이브 화면
   │  ├─ battle/               ← 묵·사연 배틀(VS, 게이지, 컷인, 등급, 의상 단계)
   │  ├─ audio/                ← SDL2_mixer(OGG 배경음악·효과음)
   │  ├─ assets/               ← 그림 로딩·해제(LRU 캐시, 장 단위 미리 읽기)
   │  └─ save/                 ← ux0:data/orpheia/ 에 JSON 세이브·기록
   └─ build/  (CI가 만든 VPK)
```

- 라이브러리(VitaSDK 패키지): SDL2, SDL2_image(PNG/JPEG), SDL2_ttf + FreeType, SDL2_mixer + libvorbis, cJSON(또는 nlohmann/json). WebP 디코더는 비타 패키지 유무가 불확실하니 **변환 단계에서 PNG/JPEG로 바꿔** 의존성을 줄인다.
- 같은 코드를 PC용 SDL2로도 빌드해서, 개발·디버깅은 PC에서 하고 비타에서는 성능·조작만 확인한다.

## 5. 변환 도구 `tools/export-vita.mjs`

웹판이 바뀔 때마다 이것만 다시 돌리면 비타 데이터가 맞춰진다.

1. **대본 → `chapters.json`**: `vn.js`의 파서를 Node에서 그대로 불러(스텁 `VN.chapter`) 장마다 op 배열과 라벨 표를 뽑는다. 웹과 같은 파서를 쓰니 해석 차이가 없다.
2. **문제 → `quiz.json`**: `data/qs.js`, `explanations.js`, `predicted.js`, `figures.js`, `predicted-figures.js`를 합친다. 자료 그림 경로는 비타 쪽 파일명으로 바꾼다.
3. **표 → `tables.json`**: `CAST`(표정 목록), `MOB_BY_NAME`, `COSTUME_EXPR`, `SONG_TITLE`·`BGM_TITLE`, 묵·사연 의상(`muk-skins.js`, `sayeon-skins.js`), 핵심노트(`data/core-notes`, HTML → 간단한 마크업 텍스트).
4. **그림**: 용도별로 줄인다(아래 표). 투명이 있는 스탠딩·SD·모브는 PNG, 나머지는 JPEG(품질 85).
5. **소리**: MP3 → OGG Vorbis(배경음악 96~112kbps 스테레오, 효과음 모노).
6. **글꼴**: 고운바탕·고운돋움·Noto Serif KR(OFL). 대사창용 1종만 상주시키고 나머지는 필요할 때 연다.

| 그림 | 웹 원본 | 비타 출력 | 예상 용량 |
|---|---|---|---|
| 배경·CG | 2432×1664 WebP | 1088×744 JPEG(화면보다 살짝 크게: 흔들림·확대 여유) | 약 60MB |
| 스탠딩 | 1664×2432 WebP | 높이 640 PNG | 약 50MB |
| 문제 자료(기출·예상) | 최대 1600 폭 | 폭 1280 JPEG/PNG(확대해서 읽어야 하므로 크게) | 약 100MB |
| 배경음악 | MP3 172MB | OGG | 약 90MB |
| **합계(VPK)** | | | **약 300~350MB** |

## 6. 화면·조작 설계 (960×544)

- **대사 화면**: 스탠딩 3자리(왼·가운데·오른)는 웹판 `fixSlots` 규칙을 그대로 옮긴다. 대사창은 화면 아래 30%. 글자 크기 22~24px(비타 5인치에서 읽히는 하한).
- **조작**(확정): ○ 확인·다음 대사, × 취소·닫기, △ 메뉴, □ 대사창 숨기기, L 로그, R 오토, START 세이브·로드, 방향키·왼쪽 스틱으로 선택지 이동. 앞 터치로도 전부 가능하게(웹판과 같은 감각). 뒤 터치패드는 쓰지 않는다.
- **퀴즈 화면**: 가장 손이 많이 간다.
  - 자료 그림 전체를 왼쪽 60%에 맞춰 보여 주되, **△로 전체 화면 확대, 오른쪽 스틱으로 이동, L/R로 확대 배율**(웹판의 "눌러서 크게 보기"를 버튼으로). 앞 터치로는 끌어서 이동, 두 손가락으로 확대.
  - 선택지 5개는 오른쪽 40%, 방향키로 고르고 ○로 답. 그림 보기는 2×3 격자.
  - 해설은 아래에서 올라오는 판, 스크롤은 오른쪽 스틱.
- **배틀**: VS 컷인·게이지·컷인 그림·등급 화면을 그대로. 파편·흔들림은 스프라이트 몇 개와 화면 흔들기로 단순화.
- **판서·기록부·갤러리**: 웹판의 탭 구조를 유지하되 한 화면에 하나씩(목록 ↔ 내용). 갤러리 차분 넘기기는 L/R.

## 7. 메모리·로딩 전략

- 그림은 **장 단위로 쓰는 것만** 미리 읽는다(변환 도구가 장마다 쓰는 그림 목록을 뽑아 둔다). 화면에 있는 것 + 다음 몇 줄 앞의 것만 VRAM에 두고 LRU로 내린다.
- 배경 1장 약 3MB(RGBA 1088×744), 스탠딩 1장 약 1MB → 동시에 배경 2 + 스탠딩 4 + UI 정도면 20MB 안팎.
- 문제 자료 그림은 퀴즈 화면에 들어갈 때 읽고 나갈 때 해제.
- 배경음악은 스트리밍 재생(통째로 메모리에 올리지 않음).
- 세이브 썸네일은 160×90 JPEG.

## 8. 단계별 일정 (주말 개발 기준 대략)

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 0. 환경 | VitaSDK 설치, GitHub Actions에 `vitasdk/vitasdk` 도커 이미지로 VPK 빌드, Vita3K(에뮬레이터)로 "안녕, 주인님" 화면 | Actions가 VPK를 산출물로 올림 |
| 1. 변환 도구 | `export-vita.mjs`로 대본·문제·표·그림·소리 내보내기 | 25장 op 수가 웹판과 같음, 그림·소리 누락 0 |
| 2. 실행기 뼈대 | 배경·스탠딩·대사·선택지·플래그·라벨·세이브 | 서장~1장을 PC 빌드로 끝까지 |
| 3. 학습 화면 | 퀴즈(확대·이동 포함)·해설·판서·기록부 | 1~3장 퀴즈를 비타 실기에서 무리 없이 읽고 풂 |
| 4. 연출 | 다이브·카드·HUD·사진 액자·휴대폰·SD·모브·한복 자동 전환·배틀 | 3장(본보기)과 11장(사연 VS 묵)이 웹판과 같은 흐름 |
| 5. 나머지 | 갤러리·회상·차분·장 선택·엔딩·묵 의상 도감·기출 풀기(모의고사) | 웹판 메뉴 전부 |
| 6. 다듬기 | 로딩 시간·메모리·글자 크기·조작감, LiveArea 꾸미기 | 실기에서 전 장 통 플레이 |

웹판에 쓰던 자동 통 플레이 테스트(Playwright)처럼, PC 빌드에 **헤드리스 자동 진행 모드**를 넣어 25장을 끝까지 돌리고 멈춤·누락 그림을 잡는다.

## 9. 위험과 대응

- **문제 자료 글씨**: 비타 화면에서 가장 큰 걸림돌. 확대·이동 조작을 3단계에서 먼저 실기로 확인하고, 안 되면 자료를 위·아래 두 화면으로 나누는 방식으로 바꾼다.
- **메모리 부족**: 큰 CG가 연달아 나오는 장(종장·하렘 엔딩)에서 위험. 장 단위 목록 + LRU로 막고, 그래도 빠듯하면 CG만 960×544 원크기로 더 줄인다.
- **한글 글꼴 렌더링 속도**: 글리프 캐시 텍스처에 자주 쓰는 2,350자를 시작할 때 미리 굽는다.
- **웹판과 어긋남**: 대본·문제는 늘 웹판이 원본. 비타 전용으로 손대는 데이터는 두지 않는다(변환 도구만 고친다).
- **배포**: 개인 기기에서 즐기는 홈브루 용도. 기출 문제 원문은 공개 배포 시 저작권을 따로 확인한다.

## 10. 정한 것 (2026.11 주인님)

- 실기: 홈브루 가능한 PS Vita, 저장 공간 200GB 이상 여유 → 용량 예산은 넉넉하다(그림을 과하게 줄이지 않는다).
- 확인 버튼 ○, 취소 ×(일본·아시아식).
- 뒤 터치패드는 쓰지 않는다. 앞 터치는 웹판처럼 쓴다.

## 11. 주인님께서 준비하실 것

1. 홈브루가 가능한 PS Vita(HENkaku 계열 환경 + VitaShell), 넉넉한 저장 공간(SD2Vita 권장, 400MB 이상 여유).
2. 실기 테스트 때 VPK를 비타로 옮기는 방법(VitaShell FTP/USB).
3. 조작 취향 결정: ○/× 배치(일본식 ○확인 vs 서양식 ×확인), 뒤 터치패드 사용 여부.
